# UI GUIDELINES

# Objetivo

Este documento define los principios de experiencia de usuario e interfaz de Rondo.

Su propósito es garantizar una experiencia consistente, simple y moderna en toda la plataforma.

Toda nueva pantalla deberá respetar estas reglas.

---

# Filosofía

Rondo es una aplicación para organizar deporte.

La interfaz debe transmitir:

- simplicidad
- velocidad
- confianza
- comunidad
- dinamismo

El usuario debe dedicar su tiempo a jugar, no a aprender a usar la aplicación.

---

# Mobile First

Toda pantalla deberá diseñarse primero para dispositivos móviles.

La experiencia desktop será una adaptación de la experiencia móvil, nunca al revés.

---

# Simplicidad

Cada pantalla debe tener un objetivo principal.

Evitar:

- exceso de botones
- múltiples acciones principales
- información innecesaria

El usuario siempre debe saber cuál es el siguiente paso.

---

# Jerarquía visual

Cada pantalla deberá tener:

- una acción principal
- acciones secundarias
- información complementaria

Nunca dos acciones con la misma importancia visual.

---

# Navegación

La navegación debe ser clara y predecible.

El usuario siempre debe conocer:

- dónde está
- cómo volver
- cuál es el siguiente paso

---

# Tiempo de aprendizaje

Un usuario nuevo debe poder utilizar las funciones principales sin necesidad de tutoriales.

La interfaz debe ser intuitiva.

---

# Feedback

Toda acción debe generar una respuesta visual.

Ejemplos:

- loading
- éxito
- error
- confirmación
- progreso

Nunca dejar al usuario sin información.

---

# Estados

Toda pantalla deberá contemplar:

Loading

Empty

Success

Error

Offline (cuando corresponda)

---

# Formularios

Los formularios deberán:

- solicitar únicamente la información necesaria
- validar en tiempo real cuando sea útil
- mostrar errores claros
- conservar los datos ante errores

---

# Mensajes

Los mensajes deben:

- ser claros
- ser breves
- evitar lenguaje técnico

Correcto:

"No pudimos reservar la cancha."

Incorrecto:

"HTTP 409 Conflict"

---

# Confirmaciones

Solicitar confirmación únicamente para acciones irreversibles.

Ejemplos:

- cancelar partido
- abandonar partido
- eliminar reserva

No solicitar confirmación para acciones frecuentes.

---

# Accesibilidad

Toda la aplicación deberá cumplir buenas prácticas de accesibilidad.

Como mínimo:

- navegación por teclado
- contraste adecuado
- etiquetas descriptivas
- foco visible

---

# Colores

El color nunca será el único indicador de estado.

Siempre deberá complementarse con:

- iconos
- etiquetas
- texto

---

# Íconos

Los íconos complementan la información.

Nunca reemplazan texto cuando la acción pueda generar dudas.

---

# Animaciones

Las animaciones deben:

- ser rápidas
- aportar contexto
- nunca bloquear la interacción

Evitar animaciones innecesarias.

---

# Rendimiento

La interfaz debe sentirse inmediata.

Objetivos:

- navegación fluida
- scroll continuo
- respuestas rápidas

---

# Consistencia

Los mismos elementos deben comportarse igual en toda la aplicación.

Ejemplos:

- botones
- tarjetas
- diálogos
- chips
- listas

---

# Búsquedas

Las búsquedas deberán responder rápidamente.

Mostrar:

- estado vacío
- resultados
- filtros activos

---

# Listados

Los listados deberán:

- soportar paginación o carga incremental
- mostrar estados vacíos
- indicar cantidad de resultados

---

# Acciones críticas

Las acciones importantes deberán destacarse claramente.

Ejemplos:

Reservar

Crear partido

Confirmar asistencia

---

# Errores

Los errores deben explicar:

- qué ocurrió
- cómo solucionarlo
- qué puede hacer el usuario

Nunca mostrar errores técnicos.

---

# Notificaciones

Las notificaciones deberán ser relevantes.

Evitar interrupciones innecesarias.

---

# Chat

El chat debe priorizar:

- rapidez
- claridad
- facilidad de lectura

La conversación nunca debe ocultar información importante del partido.

---

# Perfil

El perfil debe mostrar únicamente información útil para otros jugadores.

Evitar información irrelevante.

---

# Diseño responsive

La aplicación deberá adaptarse correctamente a:

- teléfonos
- tablets
- escritorio

Sin duplicar funcionalidades.

---

# Modo oscuro

El modo oscuro será la experiencia principal del producto.

El modo claro podrá incorporarse en futuras versiones.

---

# Experiencia

El usuario debe sentir que Rondo es:

- rápida
- moderna
- confiable
- amigable

No debe sentirse como un sistema administrativo.

---

# Principio final

Antes de incorporar un nuevo elemento a una pantalla deberá responderse:

¿Ayuda al usuario a organizar y disfrutar mejor su actividad deportiva?

Si la respuesta es no, probablemente no deba formar parte de la interfaz.
